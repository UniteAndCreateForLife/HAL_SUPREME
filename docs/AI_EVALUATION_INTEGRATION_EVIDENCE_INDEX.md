## Evaluation method

HAL distinguishes:
1. configured;
2. authorized;
3. attempted;
4. observed;
5. validated;
6. reported.

A plausible answer, configured connector, or successful-looking transcript is not treated as proof that a consequential action actually happened.

For bounded agent/tool work, preferred acceptance evidence includes:
- pinned refs/versions;
- exact synthetic or non-secret fixtures;
- reproducible commands/tool paths;
- expected vs observed results;
- deterministic checks;
- CI/test receipts where available;
- explicit limitations.

## Privacy and claim boundary

Public examples exclude credentials, OTPs, tax/bank/identity data, hidden prompts, private client content, private account state, and secret-bearing URLs.

HAL's public portfolio is self-operated engineering evidence. It should not be read as a claim that these methods were deployed for an external customer's production system unless a separate source explicitly establishes that fact.
